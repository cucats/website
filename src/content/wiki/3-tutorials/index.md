Practical, hands-on guides written by CUCaTS members. This section is deliberately open-ended: anything that someone found worth figuring out is worth writing down here.

If you have explained something to a friend more than twice, that is a strong signal it belongs on this page — see [contributing](/wiki#contributing) for how to add one.

## What makes a good tutorial

The guides we have found most useful share a few properties:

- **They solve one problem.** "Setting up OCaml for Foundations of Computer Science" is a tutorial. "Programming languages" is a textbook.
- **They are runnable.** Every command and code block should work if pasted in order, on a machine that starts from nothing.
- **They say what to expect.** Show the output, or describe what success looks like, so a reader knows whether they are on track.
- **They mention the failure modes.** The paragraph explaining the error message you spent an hour on is usually the most valuable part of the page.
- **They date themselves where it matters.** Tooling rots. If a guide depends on a particular version, say so.

Length is not a virtue. A page that saves someone twenty minutes is worth publishing.
